Zoom 3 · Architecture

Inside the engine

What "dispatch · record · verify" actually is: entry points feed one drive loop, dispatch_batch claims ready DAG nodes with a compare-and-swap, agent steps go out over the ACP transport, and everything lands in one SQLite db. The CLI's exact call order is zoom 4; a single agent turn is zoom 6.

Zoom 4 · Sequence

How the CLI drives a workflow

One orchestrator run: seed and lock the run in the db, loop dispatch → execute → record until the workflow completes, blocks, or pauses for input; unlock and archive on the way out. The Sessions path enters the same loop.

One remote step over the relay

The body of zoom 2's coral loop when a step is rostered to a remote agent: plain-language ask out, machine-local ACP at the far edge, work in the agent's own checkout, branch push, signed completion back through the trust gate. What happens inside the agent CLI is zoom 6.

Zoom 6 · Sequence

One ACP turn, end to end

The narrowest view: spawn the agent binary, negotiate the protocol with filesystem and terminal capabilities off, one prompt, streamed updates and policy-answered permissions, then a normalized result. A crash or timeout becomes a zeroed retryable result — it never raises.
